# 久谦·行业品类品牌趋势看板V2.0

正式入口：<https://yichu-zql.github.io/jq-industry-scan/>

面向行业研究的静态看板。六个入口：行业概览、类目大盘、类目价格带、竞品格局、品牌深挖、口径与数据。支持久谦一级／二级／三级分级多选、平台多选、年累计／近12个月／单月／历年／自定义月份。

## 业务口径

- 金额均为 **GMV（退后）**，使用久谦 `gmv`。沿用已有行业竞品看板口径；源表没有单列退款字段。
- 类目使用事实表自带的 `jq_cate1/2/3`，稳定ID来自完整路径的 SHA256 前16位；不通过存在多对多歧义的映射表关联扩张记录。
- 行业表先按大小写敏感的完整业务键检查冲突，再聚合。数据库默认不区分大小写，`PPR管件` 与 `ppr管件` 不能被误当成同一条重复记录删除。
- 持续下滑：最近三个完整年度同比均＜0；持续中低速增长：均＞0且三年CAGR＜20%；持续高速增长：均＞0且CAGR≥20%；其余可判定情况归“持平或波动增长/回落”。
- 判断三个年度同比需要四个完整年度。历史不足、缺月或基期非正时不强行分类。
- 增长品类：久谦三级类目，最近完整12个月GMV（退后）≥1亿元，且连续三个完整年度均增长，或三个年度中至少一年同比严格＞50%。
- 矩阵规模按截止月向前12个月，历史增长按截至截止月的最近完整年度；不把单月或年累计金额当成年规模。
- CR5和TOP3使用当期品牌排名；未知品牌计入分母、不参加排名。品牌份额与CR5使用同源品牌表总额（含未识别品牌）作为分母；跨表覆盖差异单独披露，不再隐藏份额。
- 缺失不是零。金额可显示已入库合计，但不完整范围的同比、份额变化不计算。件均价先汇总再相除。
- 价格带使用商品原始 `asp`，左闭右开；缺失和非正价格单独保留。当前采用统一绝对价格档，便于多类目比较；不同类目价位不能直接解读为同等产品档次。
- 品牌名称仅做 Unicode NFKC、首尾空白及大小写归一，不做无依据的品牌归属或系列推断。

行业概览与类目大盘的规模、销量、占比按已入库记录展示；行业同比、份额变化和件均价同比按两期共同存在的类目-月份-平台记录计算，并显示可比金额覆盖率。缺失不补零；这与增长矩阵要求四个完整年度的严格判断分开，不改变增长品类入选条件。

## 开发与验收

需要 Node.js 22+、Python 3.12+。浏览器需要支持 Module Worker、DecompressionStream。

```sh
npm ci
pip install -r requirements.txt
npm run check
node scripts/validate-release.mjs
node scripts/serve.mjs
```

本地地址 `http://127.0.0.1:8765`。预览服务只暴露前端和聚合数据，不暴露 `.private`、`.cache`、Git或脚本目录。

流畅度策略：最近截止月的近12个月、年累计、单月使用预计算品牌摘要；全品牌搜索仍在后台线程完成；只传递当前展示的品牌和合计残差，避免向主线程传递十几万个品牌。首屏并行加载行业数据与对应截止月的品牌年汇总，并提前启动计算线程；分片按内容哈希缓存；全行业和一级行业使用预聚合；重复筛选复用内存数据；解压及增长计算在 Worker 中执行；旧请求取消并检查请求版本；矩阵明细分页，宽表在自身容器内滚动。

发布前需核对：矩阵计数与明细一致、单月不改变年规模口径、平台分母一致、缺失不补零、CSV范围与当前表一致、快速切换不串页、相对路径在GitHub项目子目录下可用。实际性能记录见交付说明，不能以离线计算耗时替代网络首屏实测。

## 更新入口

源库只执行 SELECT 和会话级只读设置，不写源表。表上没有可用索引，首次和后续完整刷新采用全量快照，按一级行业分批；不宣称已实现最近三个月增量。

凭据经标准输入传给 Python。Windows无人值守更新所需配置保存在被忽略的 `.private/connection.xml`，密码必须使用当前Windows用户DPAPI加密；不提交、不上传、不打印。可通过 `JQ_DEPENDENCIES` 指向本地PyMySQL安装目录。缓存可由 `JQ_CACHE_DIR` 指定，生产刷新为每次独立候选目录。

```powershell
# 完整候选检查；不推送
pwsh -NoProfile -File scripts/refresh.ps1 -Force
# 检查源变化，有变更才刷新、校验、发布和线上复验
pwsh -NoProfile -File scripts/refresh.ps1 -Publish
```

源变化签名使用各表最大入库时间与行数；若源库原地修订且不更新入库时间、行数，需使用 `-Force` 强制刷新。失败保留线上上一成功发布；运行状态写 `.private/last-run.json`，失败返回非零退出码。不在失败时推进源签名或修改线上成功时间。自动调度的实际启用状态以页面和交付记录为准；脚本存在不等于定时任务已运行。

定时任务配置：`pwsh -NoProfile -File scripts/register-refresh.ps1`，本机北京时间每日17:30，次日起生效，要求当前用户登录和联网；禁用时加 `-Disable`。源签名在提取前后比对，提取期间源数据变化则拒绝发布。失败记录仅在本机，未配置外部消息通知。若推送失败留下未发布本地提交，定时任务会停止并要求维护时核对，不擅自推送其他改动。

## 发布与回退

沿用 `main` 分支根目录的 GitHub Pages。`.nojekyll` 保证静态文件直接发布；GitHub Actions执行检查。必须本地通过检查后才能提交推送，等待Pages完成后用 `scripts/verify_live.py` 比对线上数据版本，并用浏览器复验交互。

回退使用 `git revert` 回退有问题的发布提交，不重写历史。数据清单指向内容哈希文件，避免新旧分片混用。正式网页与仓库均公开，只有适合公开的聚合数据可以提交；数据库凭据及原始缓存必须保持忽略。


## V2.1.0 更新
- 全局吸顶导航，移除源码链接；长表默认10行分页、容器内上下滚动、固定表头。
- 平台名称集中到表头颜色图例，单元格仅显示色条和百分比；数据条与矩阵坐标轴提高对比度。
- 类目大盘采用五项KPI、平台堆叠趋势、同月同比柱图；价格带采用同期迁移、分布表和热力矩阵；竞品格局展示品牌表与月度份额；品牌深挖增加对比对象、平台分布及价格结构。
- TOP3和CR5使用同源品牌表分母。历史1%跨表审核仍保留作覆盖检查，不作为隐藏比例的条件。
- 每次发布必须更新 `lib/version.js` 和首页版本/缓存号。小修或纯数据更新运行 `python scripts/bump_version.py patch`；功能更新使用 `minor`；破坏性更新使用 `major`。无数据变化不发布、不递增版本。
- 看板版本与数据快照指纹分开，代码更新不伪造采集时间；自动更新脚本在有实质数据变更时递增补丁号。
